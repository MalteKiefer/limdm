# Languages and translation

LiMDM speaks German (`de`), English (`en`), French (`fr`), Spanish (`es`), Italian (`it`)
and Russian (`ru`). German is the source language of the console app, English the source
of every text the server, the agent and the desktop tools write.

## Which language is shown

* Console app: the language picked in the profile, the user menu or the command palette;
  until then the first browser language LiMDM speaks, else English. The choice is kept in
  the browser and sent to the server (`GET /lang/{lang}` sets the `limdm_lang` cookie), so
  texts the server writes follow it: labels of audit actions and agent events, check
  titles, problem details of the API, the sign in and error pages, schema form hints.
* Server pages without a session (sign in, errors): the `limdm_lang` cookie, else
  `Accept-Language`, else English.
* Notifications: each channel has a language (Settings, Notifications), English by default.
* Evidence PDF: French, Spanish and Italian as asked; Russian falls back to English, as the
  PDF uses the built in Helvetica fonts (WinAnsi, no Cyrillic).
* Audit log entries stay as written: the action has a translated label, the detail is the
  record itself and is not translated (the hash chain covers it).

## Where the texts live

| Texts | Place |
|---|---|
| Console app | `web/src/i18n/core.ts` and `web/src/areas/<area>/messages.ts` (German and English), `core.<lang>.ts` and `messages.<lang>.ts` for French, Spanish, Italian and Russian, loaded only for the language in use |
| Server (pages, labels, problem details, notifications, check titles, agent events) | `internal/server/i18n.go` (German), `i18n_fr.go`, `i18n_es.go`, `i18n_it.go`, `i18n_ru.go`; the English text is the key |
| Schema form hints | `internal/server/app_config_schema.go` (English and German pairs); the other languages translate the English text through the server catalogs |
| Agent events | `internal/api/events.go`: the formats by key; the server finds key and parameters of every event line (also of older agents) and shows it in the reader's language |

## Checks

* `npm run lint` (`scripts/i18n-check.mjs`): a key used but missing, a key nobody uses, and
  hardcoded visible text in the app (JSX text, `aria-label`, `title`, `placeholder`, `alt`,
  label props, `toast`). Product names, units, code and example values pass; a deliberate
  exception carries `// i18n-ok` on its line.
* `tsc`: every language catalog has exactly the German keys.
* `npm test` (`src/i18n/i18n.test.ts`): same keys, same placeholders, no empty text, and the
  Russian plural forms `one`, `few`, `many`, `other` for every plural message.
* `go test ./internal/server` (`i18n_test.go`): every server text in every language, every
  audit action, command type and agent event format with a label.
* Playwright (`web/e2e/i18n.spec.ts`): every language on the main pages, no raw key, no CSP
  error.

## Plurals

Plural messages are objects with the CLDR categories of the language and `{count}`:
German, English, French, Spanish and Italian use `one` and `other`; Russian uses `one`
(1, 21, 31 …), `few` (2 to 4, 22 to 24 …), `many` (0, 5 to 20, 25 …) and `other`
(fractions). `Intl.PluralRules` picks the category.
