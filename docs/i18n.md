# Languages and translation

LiMDM speaks German (`de`), English (`en`), French (`fr`), Spanish (`es`), Italian (`it`)
and Russian (`ru`). German is the source language of the console app, English the source
of every text the server, the agent and the desktop tools write. English is the fallback
everywhere: a text without a translation is shown in English, never as a key.

## Which language is shown

* Console app: the language picked in the profile, the user menu or the command palette;
  until then the first browser language LiMDM speaks, else English. The choice is kept in
  the browser and sent to the server (`GET /lang/{lang}` sets the `limdm_lang` cookie), so
  texts the server writes follow it: labels of audit actions and agent events, check
  titles, problem details of the API, the sign in and error pages, schema form hints.
* Server pages without a session (sign in, errors): the `limdm_lang` cookie, else
  `Accept-Language`, else English.
* Notifications: each channel has a language (Settings, Notifications), English by default.
* Evidence PDF: French, Spanish and Italian as asked; Russian falls back to English, as the
  PDF uses the built in Helvetica fonts (WinAnsi, no Cyrillic).
* Audit log entries stay as written: the action has a translated label, the detail is the
  record itself and is not translated (the hash chain covers it).
* `limdm`, the tray (`limdm-desktop`) and the GTK app: the session's locale like gettext
  picks it: `LC_ALL`, `LC_MESSAGES`, `LANG`, then the system locale (`/etc/locale.conf`,
  `/etc/default/locale`), and, unless that locale is `C`, the first supported entry of
  `LANGUAGE`. Anything else is English.
* Agent notifications: the locale of each graphical session, so two users signed in with
  different languages each get their own.
* Desktop login prompt (PAM) and `/etc/nologin` texts: the system locale.

Machine readable output stays the same in every language: the admin API's JSON, `limdm
--json`, exit codes, status codes in `limdm` tables (`PASS`, `FAIL`, `NA`), the agent
socket protocol.

## Where the texts live

| Texts | Place |
|---|---|
| Console app | `web/src/i18n/core.ts` and `web/src/areas/<area>/messages.ts` (German and English), `core.<lang>.ts` and `messages.<lang>.ts` for French, Spanish, Italian and Russian, loaded only for the language in use |
| Server (pages, labels, problem details, notifications, check titles, agent events) | `internal/server/i18n.go` (German), `i18n_fr.go`, `i18n_es.go`, `i18n_it.go`, `i18n_ru.go`; the English text is the key |
| Schema form hints | `internal/server/app_config_schema.go` (English and German pairs); the other languages translate the English text through the server catalogs |
| Agent events | `internal/api/events.go`: the formats by key; the server finds key and parameters of every event line (also of older agents) and shows it in the reader's language |
| `limdm`, `limdm-desktop`, agent notifications, PAM prompt | `internal/locale`: `tr("English text", args...)`, `trn(n, "one", "other", args...)`, `locale.T`, `locale.N`; catalogs in `internal/locale/catalog/<lang>.json`, embedded in the binaries |
| GTK app (`limdm-desktop-ui`) | Python `gettext`: `_("English text")`, `ngettext(...)`; catalogs in `packaging/locale/<lang>.po`, installed to `/usr/share/limdm/locale/` |

On the device side the English text is the key (like a gettext msgid). A JSON value is a
string, or for a text with a count the list of its plural forms. `N` and `trn` format with
the count first, so every form must keep `%d` as its first verb.

The GTK app reads the `.po` file at start and compiles it in memory for Python's `gettext`,
so the build needs no `msgfmt` and the packages ship plain `.po` files. It looks next to the
script first (`packaging/locale` in the source tree), then in `/usr/share/limdm/locale`.

Texts that come from the agent as data are passed through the catalog as well: compliance
check titles of the built in checks and the agent's error messages. Unknown texts, such as
custom checks or a message IT sends, are shown as written. The built in check titles have
the same translation in the server and the device catalogs.

## Checks

* `npm run lint` (`scripts/i18n-check.mjs`): a key used but missing, a key nobody uses, and
  hardcoded visible text in the app (JSX text, `aria-label`, `title`, `placeholder`, `alt`,
  label props, `toast`). Product names, units, code and example values pass; a deliberate
  exception carries `// i18n-ok` on its line.
* `tsc`: every language catalog has exactly the German keys.
* `npm test` (`src/i18n/i18n.test.ts`): same keys, same placeholders, no empty text, and the
  Russian plural forms `one`, `few`, `many`, `other` for every plural message.
* `go test ./internal/server` (`i18n_test.go`): every server text in every language, every
  audit action, command type and agent event format with a label.
* `go test ./internal/locale` fails when a text used in `cmd/limdm`, `cmd/limdm-desktop` or
  `internal/agent` (calls of `tr`, `trn`, `T`, `N`, `notifyUsers`, `notifyAs`, the titles in
  `checks.go`, the PAM texts) is missing in a language, a msgid of the GTK app or a check
  title is missing in a `.po` file, or a plural text has the wrong number of forms or a
  translation changes the printf verbs.
* `msgfmt -c --check-format packaging/locale/<lang>.po` checks the `.po` syntax as well.
* Playwright (`web/e2e/i18n.spec.ts`): every language on the main pages, no raw key, no CSP
  error.

## Plurals

German, English, French, Spanish and Italian use `one` and `other`; Russian uses `one`
(1, 21, 31 …), `few` (2 to 4, 22 to 24 …), `many` (0, 5 to 20, 25 …) and `other`
(fractions). French counts 0 as singular.

* Console: plural messages are objects with the CLDR categories of the language and
  `{count}`; `Intl.PluralRules` picks the category.
* Device side: a JSON list with two forms (de, en, es, fr, it) or three for Russian (one,
  few, many); `ngettext` with the `Plural-Forms` header of the `.po` file.

## Adding a text or a language

* Console: add the key to the German and English catalog and to every `<lang>.ts` file;
  `tsc` and `npm test` name what is missing.
* Server: add the German entry to `deCatalog` and the other languages to `i18n_<lang>.go`.
* Device side: write the English text through `tr`/`trn` (Go) or `_()`/`ngettext()`
  (Python), one string literal per text (the tests read the source), add the translation
  to every `internal/locale/catalog/<lang>.json` or `packaging/locale/<lang>.po`, then run
  `go test ./internal/locale`.
* A new device language: add the code to `Languages` in `internal/locale/locale.go` and to
  `LANGUAGES` in `packaging/limdm-desktop-ui`, add its plural rule to `pluralIndex` and
  `pluralForms` when it is not the one/other rule, create the JSON catalog and the `.po`
  file (with its `Plural-Forms` header) and add `Name[xx]`/`Comment[xx]` to the `.desktop`
  files in `packaging`.

## Not translated

* Messages of the package scripts (`packaging/*.sh`, `scripts/install-agent.sh`) and of
  `limdm-agent` itself: they address administrators and land in package manager and system
  logs.
* The agent log (`limdm log`, the log page of the app) and the detail line of a check: they
  are technical records, kept as written so they can be searched and quoted.
* Shutdown broadcasts (`wall`) of a restart IT requested: system wide, no user language.
