# Languages and translations

LiMDM speaks English, German, French, Spanish, Italian and Russian. English is the source
language and the fallback: a text without a translation is shown in English, never as a key.

Command names, flags, IDs and file names (`limdm software list`, `--json`, `FLATPAK_ID`)
stay English in every language. German avoids hyphenated compounds, as in the rest of the
product ("Agent Protokoll", "Geräte ID").

## Choosing the language

* Console: the browser's language, or the choice in the profile (see [console.md](console.md)).
* `limdm`, the tray (`limdm-desktop`) and the GTK app: the session's locale like gettext
  picks it: `LC_ALL`, `LC_MESSAGES`, `LANG`, then the system locale (`/etc/locale.conf`,
  `/etc/default/locale`), and, unless that locale is `C`, the first supported entry of
  `LANGUAGE`. Anything else is English.
* Agent notifications: the locale of each graphical session, so two users signed in with
  different languages each get their own.
* Desktop login prompt (PAM) and `/etc/nologin` texts: the system locale.

Machine readable output stays the same in every language: `limdm --json`, exit codes,
status codes in `limdm` tables (`PASS`, `FAIL`, `NA`), the agent socket protocol.

## Device side catalogs

| Program | Mechanism | Catalog |
|---|---|---|
| `limdm`, `limdm-desktop`, agent notifications, PAM prompt | `internal/locale`: `tr("English text", args...)`, `trn(n, "one", "other", args...)`, `locale.T`, `locale.N` | `internal/locale/catalog/<lang>.json`, embedded in the binaries |
| GTK app (`limdm-desktop-ui`) | Python `gettext`: `_("English text")`, `ngettext(...)` | `packaging/locale/<lang>.po`, installed to `/usr/share/limdm/locale/` |

The English text is the key (like a gettext msgid). A JSON value is a string, or for a text
with a count the list of its plural forms: two for de, en, es, fr, it, three for ru (one,
few, many; 1 and 21 one, 2 to 4 and 22 few, 0, 5 to 20 and 11 many). French counts 0 as
singular. `N` and `trn` format with the count first, so every form must keep `%d` as its
first verb.

The GTK app reads the `.po` file at start and compiles it in memory for Python's `gettext`,
so the build needs no `msgfmt` and the packages ship plain `.po` files. It looks next to the
script first (`packaging/locale` in the source tree), then in `/usr/share/limdm/locale`.

Texts that come from the agent as data are passed through the catalog as well: compliance
check titles of the built in checks and the agent's error messages. Unknown texts, such as
custom checks or a message IT sends, are shown as written.

### Tests

`go test ./internal/locale` fails when

* a text used in `cmd/limdm`, `cmd/limdm-desktop` or `internal/agent` (calls of `tr`, `trn`,
  `T`, `N`, `notifyUsers`, `notifyAs`, the titles in `checks.go`, the PAM texts) is missing
  in a language,
* a msgid of the GTK app or a check title is missing in a `.po` file,
* a plural text has the wrong number of forms, or a translation changes the printf verbs.

`msgfmt -c --check-format packaging/locale/<lang>.po` checks the `.po` syntax as well.

### Adding a text

1. Write the English text in the code through `tr`/`trn` (Go) or `_()`/`ngettext()` (Python).
   Keep one string literal per text: the tests read the source.
2. Add the translation to every `internal/locale/catalog/<lang>.json` or every
   `packaging/locale/<lang>.po`, using the glossary above.
3. Run `go test ./internal/locale`.

### Adding a language

Add the code to `Languages` in `internal/locale/locale.go` and to `LANGUAGES` in
`packaging/limdm-desktop-ui`, add its plural rule to `pluralIndex` and `pluralForms` when it
is not the one/other rule, create the JSON catalog and the `.po` file (with its
`Plural-Forms` header) and add `Name[xx]`/`Comment[xx]` to the `.desktop` files in
`packaging`.

## Not translated

* Messages of the package scripts (`packaging/*.sh`, `scripts/install-agent.sh`) and of
  `limdm-agent` itself: they address administrators and land in package manager and system
  logs.
* The agent log (`limdm log`, the log page of the app) and the detail line of a check: they
  are technical records, kept as written so they can be searched and quoted.
* Shutdown broadcasts (`wall`) of a restart IT requested: system wide, no user language.
